# projectM 大纲

个人媒体记录站。侧栏五块：**首页 / 电影 / 电视剧 / 图书 / 游戏**。体验接近豆瓣的「想看 / 在看 / 看过 + 打分 + 短评」，数据用正规 API 搜索入库，不爬豆瓣、不爬小黑盒。

**当前在做：游戏。** 电影 / 电视剧 / 图书阶段 2 已接上（资料卡、片单、排序、手动添加）。首页内容未定。

---

## 全局（五块共用）

单用户、本地或自托管。壳：

- 顶栏：返回 / Logo / 子标签 / 搜索（放大镜）
- 侧栏：上图标下文字（首页、电影、电视剧、图书、游戏）
- 返回键：各模块主页置灰不可点；进入卡片详情后可返回。各类型子标签分开记，侧栏切走再回来还停在离开时的 tab
- Logo 与内容区左缘对齐

核心循环：搜索外部资料 → 入库一份快照 → 自己打分、写短评、标状态。

### 数据与更新（全局，必须遵守）

任何对外拉来的数据，本地都要有一份可离线用的备份。界面默认只读本地；没网也能看列表、改记录、切 tab。

| 数据 | 本地位置 |
|------|----------|
| 条目与打分短评 | `local/dev.db` |
| Steam 资料 / 库存 / 完美 / 游戏详情 | `local/steam-cache.json` |
| 封面选用的 URL | 浏览器 `localStorage`（第一版不下载图片文件） |
| 滚动备份 | `local/snapshots/`：`dev.db` + `steam-cache.json`，有更新才写，最多 5 份 |

**什么时候才请求外部 API：**

1. 本地还没有这份数据（第一次建档）
2. 用户点了刷新（Update DB、资料卡刷新）
3. 用户连续 15 分钟没有任何操作（含切走标签后再回来已超过 15 分钟）
4. 我们改了读写逻辑，需要作废旧缓存时

搜索是用户主动操作，每次搜都走 API；搜到并加入后快照进库。切 tab、刷新页面、从详情返回，都不该再打远程。

**本地滚动备份（自动，不用手动）：** 进程在跑时每 2 小时检查一次 `dev.db` 和 `steam-cache.json`。内容相对上一份没变就不写；变了才拷到 `local/snapshots/`，最多留 5 份（更早的删掉）。站没开着不会打。不用系统计划任务。

不要按媒体类型拆三套表。**Item** 一条作品，**Entry** 我对它的记录，**Provider** 一种类型怎么搜。新类型只加 Provider + 枚举。

| 字段 | Item | Entry |
|------|------|-------|
| 关键 | `type` + `source` + `source_id`（唯一） | `item_id` 一对一 |
| 内容 | 标题、封面 URL、年份、简介快照 | 状态、评分 0–10、短评、日期 |

状态共用四个值：

| 值 | 电影 / 电视剧 | 图书 | 游戏 |
|----|------|------|------|
| `wishlist` | 想看 | 想读 | 想玩 |
| `in_progress` | 在看 | 在读 | 在玩 |
| `done` | 看过 | 读过 | 玩过 |
| `dropped` | 弃了 | 弃了 | 弃了 |

评分五星、允许半星。封面存外部 URL，第一版不下载图片。

技术已定：Next.js App Router + TypeScript；SQLite + Prisma；外部 HTTP 只在 `lib/providers/`；Key 只放 `local/.env`，只在服务端请求。换电脑整夹拷走 `local/`（Key、数据库、Steam 备份），不进 git。

禁止：爬豆瓣 / 小黑盒 / 非官方代理；社交、推荐、用户系统；为每种媒体复制一套业务代码。

`/search`：类型 + 关键词；结果可加入；已入库的标出来。没有 Key 的类型明确提示「未配置」。

## 电影

路由：`/?type=movie`；详情 `/item/[id]`

| | |
|--|--|
| Provider | TMDB `/search/movie`、`/movie/{id}`，语言 `zh-CN` |
| Key | `TMDB_API_KEY` |
| 子标签 | 全部 / 想看 / 在看 / 看过 / 弃了 / 片单 |
| 详情 | 资料卡、状态、评分、短评、日期、加入片单；可刷新 TMDB 快照 |

**状态：** 阶段 2 已接上。资料卡来自 TMDB（类型、导演、主演、国家、片长、上映）。列表有副标题、排序、按类型筛。顶栏有片单。搜不到可手动添加。不自己打标签。不展示社区均分。暂不做季/集进度、再看。

## 游戏（当前重点）

路由：`/?type=game`；详情 `/steam/[appid]`

| | |
|--|--|
| Provider | Steam Web API，语言简中 |
| Key | `STEAM_API_KEY`（搜索、成就、迷你资料背景） |
| 资料栏 | `STEAM_STEAMID`；家庭库还要 `STEAM_ACCESS_TOKEN` / `STEAM_REFRESH_TOKEN` |

### 子标签

隐藏 / 私人游戏全程排除。

| 标签 | 规则 |
|------|------|
| 最近游玩 | 近两周有时长，且在账号库或家庭库；按近两周时长排 |
| 全部游玩 | 有时长，且在账号库或家庭库；按总时长排 |
| 完美通关 | 全成就，且在账号库或家庭库；按全成就完成时间排 |
| 库存游戏 | 账号库 |
| 家庭库 | 家庭库中且不在账号库 |
| 想玩 | 本地想玩记录，不含已在账号库或家庭库的 |

### 已做成

- 资料栏是固定小长方形：头像 + 名字/状态（在线、离线、游玩xxx中只显示一个）/ 公开资料；下面先游玩时长、再库存价值（标签和数字同一行）。迷你资料背景铺在这张卡上。卡右下角单独刷新资料（头像/状态/背景/等级），不拉库存；页面右侧 Update DB 才拉整库。卡和刷新之间：等级+经验条、库存/家庭库/完美/想玩数量（只展示）、近两周封面按实际数量最多五张；经验条宽度按四张封面对齐
- 卡片统一尺寸：封面、标题、总时长、近两周、成就、购入价/原价（未填购入价则按原价）。全成就彩色边框
- 账号库存原价含已购 DLC。详情列出全部 DLC，可单独填购入价。购入合计 = 本体（购入或原价）+ 已购 DLC（购入或原价），未购但填了购入价的也加进合计
- 详情资料栏：标题与封面顶对齐且只占一行（超出省略）；总时长 / 近两周小时数加粗；本体与合计两行始终显示；评价；简介最多三行；商店链接与封面底对齐。购入价在详情页填
- 成就进度只用不过期的 Web API Key
- 私人/隐藏名单需要登录 token 才能向 Steam 拉新的；token 不可用时沿用上次备份，避免刷新后重新露出来
- 有 `local/steam-cache.json` 就只读备份；没有才拉一次 Steam 建档。切 tab、刷新页面、从详情返回都不打远程。资料行右下角按名称筛当前列表；从详情返回时保留 tab、筛选和滚动位置
- 更新只在：用户点 Update DB / 资料刷新，或连续 15 分钟无操作后自动拉一次。库存带上 Steam 默认隐藏的未审核/成人向等（`skip_unvetted_apps=false`）。改 `local/.env` 里的 Steam token 后也要点刷新。Steam 连不上时用备份
- 游戏详情（简介 / DLC / 成就）第一次打开写入同一份备份，之后同样只在刷新或空闲 15 分钟后更新
